# AI Assisted Development

> AI Agent Desktop Companion AI 协作开发规范

版本：v0.1

# 1. 文档目的

本文档定义如何在项目生命周期中使用 AI 工具提升开发效率。

目标：

-   提高开发速度
-   降低重复工作
-   保持架构一致性
-   保证代码质量

------------------------------------------------------------------------

# 2. AI 协作原则

## 2.1 AI 是开发助手，不是架构决策者

AI 可以：

-   编写代码
-   分析问题
-   生成测试
-   优化实现

Human 负责：

-   架构决策
-   技术选型
-   产品方向
-   最终审核

------------------------------------------------------------------------

## 2.2 文档优先

所有重要变更：

    Idea

    ↓

    Design

    ↓

    Implementation

    ↓

    Test

    ↓

    Documentation

避免：

    直接生成代码

    ↓

    发现问题

    ↓

    返工架构

------------------------------------------------------------------------

# 3. AI 使用场景

# 3.1 项目分析

用途：

-   阅读代码
-   分析架构
-   查找问题

Prompt 示例：

    请分析当前模块。

    要求：

    1. 描述当前架构
    2. 找出潜在问题
    3. 不修改代码
    4. 给出优化建议

------------------------------------------------------------------------

# 3.2 功能开发

流程：

    需求

    ↓

    AI 生成方案

    ↓

    人工确认

    ↓

    AI 实现

    ↓

    测试

AI 输出要求：

-   修改文件列表
-   实现方案
-   风险点
-   测试计划

------------------------------------------------------------------------

# 3.3 Code Review

AI 用于：

-   查找 Bug
-   检查类型问题
-   检查架构违规

Prompt：

    请 Review 当前修改。

    重点检查：

    - 架构一致性
    - 类型安全
    - 性能问题
    - 潜在 Bug

------------------------------------------------------------------------

# 3.4 测试生成

AI 可以生成：

-   Unit Test
-   Integration Test
-   E2E Test

重点覆盖：

-   Event Bus
-   State Machine
-   Plugin
-   IPC

------------------------------------------------------------------------

# 4. 文档同步流程

代码变化：

    Code Change

    ↓

    Check Documentation

    ↓

    Update Docs

    ↓

    Commit

需要同步：

-   API 文档
-   Architecture 文档
-   ADR

------------------------------------------------------------------------

# 5. AI 与 Git 工作流

推荐流程：

    Issue

    ↓

    AI Analysis

    ↓

    Branch

    ↓

    Implementation

    ↓

    Test

    ↓

    Review

    ↓

    Merge

Branch 示例：

    feature/pixi-renderer

    fix/event-bus-error

    refactor/runtime-api

------------------------------------------------------------------------

# 6. AI 自动化任务

未来可以自动化：

## 每次提交

检查：

-   类型错误
-   测试失败
-   文档遗漏

------------------------------------------------------------------------

## 每次 PR

AI 自动：

-   总结修改
-   检查风险
-   生成 Review 建议

------------------------------------------------------------------------

## 每周维护

AI 自动：

-   检查依赖更新
-   分析技术债
-   更新文档

------------------------------------------------------------------------

# 7. Codex 使用规范

## 开发前

必须提供：

-   目标
-   相关文档
-   限制条件

------------------------------------------------------------------------

## 开发中

要求：

-   小步修改
-   保持模块边界
-   输出变更说明

------------------------------------------------------------------------

## 开发后

要求：

输出：

    Changed Files

    Implementation Summary

    Test Result

    Potential Risks

------------------------------------------------------------------------

# 8. 不推荐的 AI 使用方式

## 一次生成整个项目

问题：

-   架构不可控
-   后期维护困难

------------------------------------------------------------------------

## 无测试提交

问题：

-   隐性 Bug 增加
-   回归风险提高

------------------------------------------------------------------------

## 让 AI 自行决定架构

问题：

-   容易偏离项目目标

------------------------------------------------------------------------
