# Codex Workflow

> AI Agent Desktop Companion Codex 协作开发规范

版本：v0.1

# 1. 文档目的

本文档定义如何使用 Codex 参与项目开发。

目标：

-   保证 AI 生成代码符合架构设计
-   降低 AI 自由发挥导致的架构偏移
-   建立稳定的人机协作流程

------------------------------------------------------------------------

# 2. 协作模式

项目采用：

    Human

      ↓

    Architecture Decision

      ↓

    Codex Implementation

      ↓

    Automated Verification

      ↓

    Human Review

职责分工：

## Human

负责：

-   架构决策
-   产品方向
-   技术选型
-   代码审查

## Codex

负责：

-   编写代码
-   重构
-   补充测试
-   生成文档

## Automated Test

负责：

-   验证功能
-   防止回归
-   保证质量

------------------------------------------------------------------------

# 3. Codex 开发原则

## 3.1 先理解，再修改

Codex 不应该直接开始编码。

执行顺序：

    Read Docs

    ↓

    Inspect Code

    ↓

    Explain Plan

    ↓

    Implement

    ↓

    Test

    ↓

    Report

------------------------------------------------------------------------

## 3.2 文档优先

实现功能前必须阅读相关文档。

优先级：

    ADR

     >

    Architecture

     >

    API

     >

    Design

     >

    Implementation

     >

    Task

例如：

实现 Renderer：

必须阅读：

    docs/adr/002-pixi-renderer.md

    docs/api/renderer-api.md

    docs/architecture/renderer-pipeline.md

------------------------------------------------------------------------

# 4. Feature 开发流程

## Step 1：创建任务

每个功能先明确：

-   目标
-   范围
-   不包含内容

示例：

    实现 PixiJS Renderer MVP

    包含：

    - Canvas 初始化
    - Sprite 加载
    - Animation Loop


    不包含：

    - Live2D
    - Three.js
    - 角色市场

------------------------------------------------------------------------

## Step 2：Codex 分析

Prompt 示例：

    请阅读：

    - AGENTS.md
    - 相关 docs


    不要修改代码。

    先输出：

    1. 实现方案
    2. 修改文件
    3. 风险点
    4. 测试方案

------------------------------------------------------------------------

## Step 3：实现

确认方案后：

    开始实现。

    要求：

    - 遵守项目架构
    - 添加必要类型
    - 不引入无关依赖
    - 添加测试

------------------------------------------------------------------------

## Step 4：验证

Codex 必须执行：

### Build

    pnpm build

### Test

    pnpm test

### Runtime Check

确认：

-   应用启动
-   功能正常
-   无明显异常

------------------------------------------------------------------------

# 5. Codex Prompt 模板

## 新功能开发

    你现在负责实现一个新功能。


    请先阅读：

    [相关文档]


    目标：

    [功能描述]


    要求：

    1. 不改变现有架构
    2. 遵守 API 设计
    3. 提供实现计划
    4. 实现后运行测试


    输出：

    - 修改文件
    - 实现说明
    - 测试结果

------------------------------------------------------------------------

## Bug 修复

    请调查以下问题：

    问题：

    [描述]


    请先：

    1. 定位原因
    2. 分析影响范围
    3. 提出修复方案


    确认后再修改代码。

------------------------------------------------------------------------

## 重构

    请进行代码重构。


    要求：

    - 保持行为不变
    - 提升可维护性
    - 不改变公共 API


    先输出重构计划。

------------------------------------------------------------------------

# 6. 禁止事项

Codex 不应该：

## 禁止直接增加依赖

除非说明：

-   为什么需要
-   替代方案
-   影响

------------------------------------------------------------------------

## 禁止绕过架构

例如：

错误：

    React Component

    直接控制

    Pixi Sprite

正确：

    React

    ↓

    Runtime API

    ↓

    Renderer

------------------------------------------------------------------------

## 禁止大范围重构

单次修改：

优先：

-   一个模块
-   一个目标
-   一个验证周期

------------------------------------------------------------------------

# 7. 测试流程

## 单元测试

负责：

-   Event Bus
-   State Machine
-   Runtime

工具：

    Vitest

------------------------------------------------------------------------

## 集成测试

负责：

-   Plugin
-   IPC
-   Agent Event Flow

------------------------------------------------------------------------

## E2E 测试

工具：

    Playwright

验证：

-   应用启动
-   窗口行为
-   UI 状态

------------------------------------------------------------------------

# 8. Code Review Checklist

提交前检查：

## 架构

-   [ ] 是否符合设计文档
-   [ ] 是否违反模块边界

## 类型

-   [ ] 是否有明确类型
-   [ ] 是否避免 any

## 测试

-   [ ] 是否新增测试
-   [ ] 是否验证关键流程

## 性能

-   [ ] 是否影响 60 FPS
-   [ ] 是否增加不必要渲染

------------------------------------------------------------------------

# 9. Commit 规范

格式：

    type(scope): message

类型：

    feat

    fix

    refactor

    docs

    test

    chore

示例：

    feat(renderer): add pixi sprite loader

    fix(runtime): fix state transition

    docs(api): update event protocol

------------------------------------------------------------------------
